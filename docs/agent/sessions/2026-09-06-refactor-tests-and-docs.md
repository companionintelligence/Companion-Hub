## Goal

The Stage 1 refactor turned four protected methods and a five-way duplicated switch into modules that
can be reached directly. Cash that in: write the tests that were previously impossible, and bring the
docs in line with the structure that now exists.

---

## Steps taken

1. Wrote seven test files covering the modules the refactor exposed, one agent per file.
2. Audited each by **mutation**: deliberately break the source, confirm a test fails, restore. Every
   file came back "solid" but with named survivors.
3. Ran a second pass to close the flagged gaps, again proved by mutation.
4. Updated the docs that described a structure no longer in the tree, and wrote the missing
   development-setup page.

---

## Decisions

| Decision | Rationale |
|----------|-----------|
| Audit by mutation, not by reading | A test that reads well can still pass when the code is broken. The first pass produced 219 passing tests; mutation testing showed 75 deliberate bugs survived them. That gap is invisible to review. |
| Second pass instead of accepting "solid" | Every file passed its audit, and every file still had decorative tests. `failure-reporting`'s entire network-overlap reporting branch was unasserted — the branch that actually recurs in production subnet recovery. |
| De-collide fixtures rather than add assertions | Several tests could not distinguish passthrough from hardcoding because the fixture's values *were* the constants under test. Changing the fixture to values that cannot collide fixed more than any extra assertion would. |
| Documented three latent hazards, did not fix them | All three are real but out of scope for a test-and-docs PR, and each changes a signature or adds a guard that deserves its own review. Listed under handoff. |
| Did not touch `docs/CI.md` | Its header says it is generated by `ci-local docs`. `ci-local` is not on this machine, so a hand-edit would be reverted on the next regeneration. The setup content went to a new page instead. |
| Did not touch `docs/system/desktop.md` | It describes `hub_manager.rs`, which this work did not change. Stage 1a (the Rust split) is still blocked; editing that doc now would describe work that has not happened. |

## Open items / handoff

**Three latent hazards found while writing tests. Each is characterized by a passing test that
documents today's behavior, so changing it will be a deliberate act, not a surprise:**

1. `commands/failure-reporting.ts` — `reportCommandFailure` calls `errorReportingService?.reportAppFailure`
   unguarded. A reporting transport that throws propagates out of `reportAndTranslateAppError` and
   destroys the classified `AppCommandFailureResult` the queue worker was about to reply with; the
   caller gets a raw transport error instead of the failure. Wrapping it in try/catch is a one-line
   fix, but it changes what the queue sees.
2. `inference/backends/backend-registry.ts` — `get(type)` declares a non-optional `InferenceBackend`
   return, yet returns `undefined` for any string outside the union. Three call sites feed it data
   rather than literals (`model-puller` from catalog rows, `mcp/tools/inference.tools.ts` from
   request bodies, `hub-pool-proxy` from DB columns), so a stale backend name yields a downstream
   `TypeError` instead of a typed error. Returning `InferenceBackend | undefined` pushes the check to
   those three.
3. `commands/network-recovery.ts` — with `maxAttempts = 0` the loop never runs and the function
   throws `Error("undefined")`, because `lastError` is still undefined and `String(undefined)`
   becomes the message. Either reject `maxAttempts < 1` up front or drop the final throw.

**`cargo test` remains blocked** — the Tauri Linux stack is not installed. The full apt line is now
in `docs/DEVELOPMENT_SETUP.md`. Stage 1a (splitting `hub_manager.rs`, 11,338 lines) still should not
start without it, since its verification is a before/after test count.

**Coverage deliberately left open**, each with a reason recorded in the workflow output: `hub-context`
does not cover `envOverridesForContext` / `applyDockerEnginePin` / `ensureApplianceInstall`, which
shell out to real `docker` and would need module mocks injected into a file that deliberately uses
on-disk fixtures — worth its own file. `scripts/lib/cli-compose-env.ts` has no test file at all;
`getEnvFileOrExit`'s exit path can only be reached from there.
