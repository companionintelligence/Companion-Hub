## Goal

Make the single-service QA runner reliable for manifest volumes that require Linux ownership semantics when it runs through Docker Desktop on macOS or Windows. Preserve seeded data and limit cleanup to scratch volumes generated by this QA invocation.

## Steps taken

1. Compared the narrow QA volume change already merged to `dev` with the older `main` runner; used a clean isolated worktree based on `origin/main`.
2. Added a platform-aware fallback, run-scoped managed volume names, explicit guarded cleanup, focused unit tests, and operating documentation.
3. Validated the focused tests and reviewed the remaining fleet, Marketplace, Portal, disk, and Tailscale gates.
4. Dispatched the exact Hub CI workflow; its lint step exposed five existing warnings. Removed both unsafe test assertions, escaped two shell template placeholders correctly, and removed one unused type import.

## Decisions

| Decision | Rationale |
|----------|-----------|
| Use named volumes only for unseeded declarations that explicitly set `requiresPosixPermissions: true`. | Avoid changing ordinary bind mounts or mounts carrying seed data. |
| Default on for macOS/Windows and off for Linux, with a `QA_POSIX_VOLUME_FALLBACK` override. | Docker Desktop runs containers in a Linux VM; Linux fleet hosts already provide native POSIX bind semantics. |
| Give each run a unique generated volume name and remove only names tracked by that process. | Avoid touching app volumes or stale volumes from unrelated runs. |
| Keep the change on a `main`-based branch instead of merging the widely diverged `dev` history. | Preserve the independent release line and backport only the QA behavior. |
